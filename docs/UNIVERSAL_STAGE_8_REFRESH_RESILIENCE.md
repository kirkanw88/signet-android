# Universal — этап 8: устойчивость обновления подписок

База: этап 7 (`feature/universal-stage-7-provider-tests`), успешно прошедший Android CI.

## Изменения
- При попытке заменить ранее полученный **полный XRAY_JSON** на URI-формат сервисом подписок старая конфигурация сохраняется. Для Universal дополнительно фиксируется ошибка **именно проблемной подписки**, а не просто общая всплывающая строка. Это облегчает диагностику по нескольким провайдерам.
- В инструментальные Android-тесты добавлен сценарий `failedProviderRefreshRetainsProfilesSelectionAndOtherSources`:
  - два независимых фиктивных источника без внешней сети и реальных ключей;
  - выбор сервера и добавление его в избранное;
  - попытка обновления одним повреждённым JSON;
  - проверка сохранности рабочего профиля, выбора, избранного и второй подписки;
  - повторное обновление корректной конфигурацией и очистка сообщения об ошибке;
  - удаление только тестовых данных в `finally`.
- Проверка CI теперь требует 6 UI/instrumentation тестов и отдельно 11 нативных, без отключения предыдущих тестов.

## Ограничения
- Тест некорректного обновления выполняется на искусственном локальном JSON. Он **не проверяет** ответы живого провайдера или доступность сети.
- Живые HTTPS-подписки Remnawave с HWID, сроками действия и отклонёнными устройствами должны проверяться отдельно.
- Не утверждается, что отмена обновления, параллельное обновление восьми источников и смена мобильной сети уже полностью протестированы.
- AUTO остаётся исключительно профилем, предоставленным сервером; логика Xray, DNS, routing и balancer не меняется.
- Для production необходимы проверки Android на физическом устройстве, доступности, безопасности и соответствия планеты согласованному макету.
