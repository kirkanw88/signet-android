# Signet VPN 0.2.10 — универсальная версия

Только `com.signet.client.external`, code 12. Signet с кабинетом остаётся на 0.2.6; инфраструктура и панель не изменяются.

- Подписки автоматически обновляются с целевым интервалом один час при наличии сети. Прежнее шестичасовое задание заменяется через WorkManager UPDATE; проверка срока больше не зависит от `profile-update-interval` провайдера. Локальные JSON без URL не запрашиваются. Это системная фоновая работа: Doze и ограничения Android могут задержать фактический запуск, точная минута не гарантируется.
- Качество всегда High, включая сохранённые ранее Balanced/Battery Saver. Выбор качества убран. Высокое качество применяется при создании GL-контекста, а не только после его запуска. Уменьшение движения остаётся доступно; прежние ограничения размеров базовых текстур и освобождение GL при паузе сохранены.
- Проверка новых версий всегда включена, включая установки со старым выключенным переключателем. Сам переключатель убран. Баннер и диалог остаются частью интерфейса приложения, Android-разрешения не обходятся; проверка выполняется при открытом приложении по прежней политике 15 минут после успеха / 2 минуты после ошибки.
- В списке, на главном экране, в заголовке шаблона и VPN-уведомлении используются названия хостов (`remarks`) из Remnawave, например Signet_Latvia. Флаги/география планеты сохраняются отдельно. Транспорт/JSON и описание провайдера сохранены.
- Серверные строки компактнее: вертикальные отступы 7 вместо 12 dp, заголовок 14 sp, описание одна строка, минимум 56 dp с увеличением при крупном шрифте. Рамка выбранного сервера сохранена.
- Шапка/фильтры списка входят в общую LazyColumn. Главная прокручивается по всей области содержимого, включая область планеты. Вертикальный жест освобождается для родителя, горизонтальный вращает Землю. Настройки и подписки сохраняют прокрутку на всю ширину.

## Повторная DNS-ошибка при проверке соединения

Добавлен резервный DNS-путь для проверки HTTPS через активный TUN. Если системный resolver возвращает UnknownHostException (в том числе при устаревшем отрицательном кеше), A/AAAA запрашиваются по TCP у **того же виртуального DNS-моста 172.19.0.2**, использующего DNS/routing JSON-профиля. Сокет не защищается от VPN и не привязывается к физической сети. Внешние DoH/DNS-сервисы и фиксированные IP адреса сайта не подставляются.

Ответ проверяется по transaction ID, вопросу, типу/классу, QR/RCODE/TC и границам пакета; циклы compression pointers отклоняются. Таймаут 2 секунды на TCP-запрос, максимум 65535 bytes. При отсутствии действительного ответа остаётся ошибка DNS; успешное подключение требует настоящего HTTPS с проверкой сертификата. В журнале доступны TUNNEL_FALLBACK / TUNNEL_FALLBACK_OK / TUNNEL_FALLBACK_FAILED без имён доменов и адресов серверов.

Прежний адрес проверки по умолчанию `https://example.com` однократно переводится на `https://www.gstatic.com/generate_204`; другие пользовательские адреса сохраняются. После миграции адрес по-прежнему можно менять. Ping URL по умолчанию не изменяется.

Точная причина нового сообщения на телефоне без журнала не подтверждена. Локальные tests проверяют восстановление после ошибки системного DNS через настоящий TCP fixture и сохранение ошибки при неработающем резервном пути; это не тест реального Android TUN/подписки пользователя. Результаты и ограничения: [TEST_REPORT](TEST_REPORT.md).
