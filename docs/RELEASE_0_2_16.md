# Signet VPN 0.2.16 — загрузка снимка после готовности VPN

Только universal `com.signet.client.external`, code 18. Установите поверх 0.2.15.

В 0.2.15 запрос снимка начинался уже на CONNECTING; переход в CONNECTED не менял ключ эффекта загрузки. Если DNS/запрос обрывался при создании TUN, состояние «недоступен» оставалось и после успешного подключения. Это подтверждённый дефект кода; точная ошибка телефона без диагностического кода не установлена. Контрольный запрос к MapTiler с текущим ключом сейчас возвращает HTTP 200/image/jpeg.

- Загрузка начинается только после CONNECTED и короткой паузы 350 мс для завершения переключения сети. При переподключении старый запрос отменяется, после готовности начинается новый.
- Для временного DNS/сетевого отказа, таймаута или 5xx есть один повтор через секунду. Ошибки ключа, квоты, TLS, отсутствующего участка или некорректного ответа автоматически не повторяются.
- При активном TUN и ошибке системного DNS используется существующий DNS-мост того же VPN. Внешний DNS, физический обход VPN, подставленные IP и ослабление TLS не добавлены.
- Tiles загружаются группами максимум по три параллельных запроса. Это уменьшает задержку на маршрутах с большим RTT. Запись в мозаику остаётся последовательной; кэш по-прежнему 8 МБ, ответ — максимум 512 КБ, вся попытка — максимум 25 секунд.
- Вместо одной общей ошибки показываются причина и безопасный код (`DNS`, `TIMEOUT`, `AUTH`, `QUOTA` и другие), доступна кнопка «Повторить». При включённом журнале записываются только события IMAGERY и код, без URL, API-ключа или тела ответа.

Ошибка фотографии не меняет статус VPN. Источник остаётся MapTiler Satellite, старые подписки/маршрутизация/ключ не меняются. Физический Android пока не проверен; результаты и ограничения — [TEST_REPORT](TEST_REPORT.md).
