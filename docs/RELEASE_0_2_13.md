# Signet VPN 0.2.13 — полный JSON при добавлении подписки

Универсальная редакция `com.signet.client.external`, code 15. Устанавливается поверх предыдущей universal без удаления данных.

При первом запросе к исходному адресу подписки теперь передаётся совместимость с расширенными Xray JSON-профилями: `Happ/compatible SignetVPN/<actual version>`. Реальное название/версия Signet остаются в User-Agent; версия чужого приложения не выдумывается. Прежде этот режим использовался только при дополнительном запросе `/json`: если шлюз обслуживал JSON только на исходном адресе по User-Agent, сохранялся URI без JSON-only AUTO.

Если исходный адрес вернул корректный полный JSON, он импортируется сразу, без запроса `/json`. Если ответ содержит URI, остаётся дополнительный запрос `/json` на том же origin и безопасный fallback для провайдеров только с URI. Каждый источник согласует формат независимо, включая вторую и последующие подписки и адреса с готовым `/json` или `.json`.

Существующая JSON-подписка больше не заменяется URI-ответом при временном отказе JSON: прежние профили, AUTO и настройки остаются, приложение сообщает об отказе обновления. Поддержка URI-only подписок сохраняется. AUTO импортируется только если доставлен сервером; локальная подмена URI на «JSON» и выдуманный AUTO не добавлялись. Routing, DNS и полный набор outbounds сохраняются.

Для ранее добавленной URI-подписки после установки нажмите ↻ в её шапке. Удалять или заново добавлять её не нужно. Новые подписки используют исправленное согласование при первом добавлении.

Контракт проверен по исходникам Remnawave: [extended/JSON clients](https://github.com/remnawave/backend/blob/main/src/modules/subscription-template/constants/extended-clients.ts), [base response format](https://github.com/remnawave/backend/blob/main/src/modules/subscription/subscription.service.ts). Правила конкретного провайдера могут ограничивать выдаваемый формат; наличие AUTO подтверждается только фактически доставленным JSON.
